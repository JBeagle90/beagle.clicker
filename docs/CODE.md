# The game's code: a guide for the next update

Kept by every update, for the next one. Keep it true, short (under 16 KB) and useful. Fix what's wrong,
add what you wish you'd known, and cut what no longer helps. The rules are in CLAUDE.md, not here.

Each biscuit has `hits` left: `newBricks()` gives `SPRINKLE.count` random ones 2 (drawn with `sprinkles(b)` at the fixed `SPOTS`); a hit that leaves one calls `shake(b)`, which flings the sprinkles out as `confetti`. `newBricks()` also marks `RAINBOW.count` other ones `rainbow` (filled by `rainbow(b)`, a gradient of `RAINBOW.colors`; worth `RAINBOW.points`); breaking one calls `cheer(b)`: a "+50" in `pops` and a ring of rainbow `confetti`. ## How to…

- **Add an upgrade**: one entry in `UPGRADES` (`rules.js`), in price order (a test checks). The shop shows it by itself. Update the table in `docs/GAME.md`.
- **Add a boost**: one entry in `BOOSTS` (`boosts`: the upgrade's id, `needs`, `cost`). It shows in the shop once unlocked.
- **Add a trophy**: one entry in `TROPHIES` with `when: p => …` over the saved player (`p.pats`, `p.earned`, `p.owned`, `p.game`). The server awards it on the next sync and the page announces it. Trophies are kept for good: never remove one.
- **Change the treasure**: `TREASURE` in `rules.js` (timings, reward). Another server-timed event can copy its shape: a `game.<thing>At` set in `sync`, and an action that checks `now`.
- **Change what a pat or a second gives**: `perClick` / `perSecond` in `rules.js`, or the sums there.
- **Keep something new in the save** (e.g. golden bones collected): put it under `player.game` (e.g. `game.goldenBones`). It's sent to the browser as `game.me.game`. Read it with a default: `(p.game.goldenBones || 0)`.
- **Let players do something new that changes the save**: add `actions.<name> = async ({ player, body, now }) => …` in `api/src/game/index.js`. Call `sync(player, {}, now)` first, then return `{ player, body }` or `{ error }`. From the page, call `spend("POST", "/game/<name>", body)` (from `src/game.js`). Work out rewards on the server, and check time on the server (`now`), not the browser's word.
- **Something only on the page** (an animation, a sound made with the Web Audio API, a look): `src/` and `web/` alone. Use CSS tokens for colours and check dark mode.
- **Test it**: a `dev/test-<thing>.cjs` like `dev/test-rules.cjs` (`const { test, eq, ok, done } = require("./t.cjs")`).
- **See it**: `node dev/look.mjs --pats 200 --click ".item[data-id='chew-toy']"`, then `--dark`, then `--phone`.

## Lessons

- The server caps pats at 20 a second, so `look.mjs --pats` waits between batches.
- The game's tests (`dev/test-rules.cjs`, `dev/test-treasure.cjs`) pass `rand` to `sync` to fix when the treasure comes. Trophies make bones fractional (x1.01…): compare with a tolerance, not exact numbers. An action's bones include the digging since the last sync: compare with `sync(p, {}, now).bones`, not `p.bones`. A trophy test for a count (e.g. 10 gold chests) can start the save one short (`game: { golds: 9 }`, or `pats: 99999` and a sync of `{ pats: 1 }`) and add one. A new trophy can sit anywhere in `TROPHIES` (the screen keeps that order; saves keep ids).
- To see another screen in a screenshot: `--eval "location.hash = '#stats'"`. To see the gear: `--eval "document.getElementById('beagle').classList.add('has-helmet','has-goggles','has-space')"`. New gear for the corgi is a `g` in the SVG, a `.has-<thing>` toggle in main.js's `"owned"` handler and two CSS lines: no server change. Use `wear("has-<thing>", on, cheer)`: it skips the toast on the first `"owned"` (the save loading). Something worn on the neck can sit behind `.head` in the SVG, so the head hides its top. A frenzy: set `BC.game.me.game.frenzyUntil` to `Date.now() + BC.game.skew + 20000`.
- `look.mjs --eval` can `await` (click a shop item, wait 3 s for the sync, read `BC.game.me`). A value you set on `BC.game.me` lasts only until the next sync (~1 s): shoot within that, or hold it with `setInterval`. Sniffing School is unlocked at exactly 10 Sharp Noses: test "locked" with 9.
- `look.mjs` runs `--click` before `--eval`, and `--eval` code with no `return` runs only its first statement (it's wrapped as `return <code>`): end it with `return 1`. To see the chest (the server refuses a click on it), a sync would overwrite it, so hold it: `const t = Date.now() + BC.game.skew; setInterval(() => { BC.game.me.game.treasureAt = t; BC.game.me.game.treasureGold = true; }, 10); await new Promise(r => setTimeout(r, 800)); return 1` (`streak = 4` for the flame).
- The CSP blocks inline styles in HTML, but setting `el.style.x` from JS is fine. To animate a part of an SVG (the chest's lid), use `transform-box: view-box` and a `transform-origin` in viewBox units. To catch an animation mid-way, `look.mjs --eval` can click and then wait ~300–400 ms before the shot (the chest click works even though the server refuses it; keep the `setInterval` holding `treasureAt` running, or the chest hides before the click). To have something rise out of the chest, draw it before `.chest-box` so the box hides its bottom.
- A mini game can have its own screen and draw on a `canvas` (the guard allows it; `fillText` isn't HTML). Read colours from the CSS tokens with `getComputedStyle` so dark mode works, and stop its `requestAnimationFrame` loop when its tab is hidden. To play it in `look.mjs --eval`, dispatch `KeyboardEvent`/`PointerEvent` on the canvas; its state is module-private, so to force a chance (a golden biscuit) set `Math.random = () => 0.01` in the eval first. To see a moment you can't play to (a level cleared), add a throwaway `window.__x = () => …` in `start()`, call it from `--eval`, and delete it before the guard (it worked for a mid-wiggle paw too: call it, wait ~90 ms, shoot). `look.mjs` starts its own server: no need for `npm start` first. Anything that moves in `step` must run before its `if (ball.stuck) return`.
- Sound: the browser's `speechSynthesis` (words) and Web Audio (beeps) need no files and pass the guard; both only play after a click, which Play already is. Bone Breaker has the one sound switch (`sound` in bricks.js): a new Bone Breaker sound should check it rather than add another button. To check a sound plays, `--eval` can swap `window.AudioContext` for a subclass counting `createOscillator` calls, then go to `#play`, click `#bricks-go` and dispatch a Space keydown on `#bricks`. To hit a chosen biscuit, a throwaway `window.__x` in `start()` puts the ball just under it (`ball.stuck = false`, `vx = 0`, `vy = -200`).
- Animation whose speed changes: drive it from `frame` with a phase and `setAttribute("transform", …)`; changing a CSS `animation-duration` mid-way makes it jump.
- The dog is a corgi, but its code names stay "beagle" (`#beagle`, the site's name): say "corgi" only in what players read. The SVG (viewBox 200): the head is x 36–164, y 41–159; the pointy ears go from its top out to tips near (34, 8) and (166, 8), past the helmet. The favicon is a copy of the face: change both together.
